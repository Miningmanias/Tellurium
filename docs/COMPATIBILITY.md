# Compatibility with other mods

Trial of 2026-10-05 on the reference host (NeoForge 21.1.176, Minecraft 1.21.1,
RTX 5070 Ti), each mod at its newest NeoForge 1.21.1 release on Modrinth that
day, with ScalableLux. Reproduce with `python scripts/test-worldgen-mods.py`
(it downloads the mods, verifies their hashes and runs each group).

## How to read the table

Each group ran on a fresh dev server with `gpu.mode = "check"` and the built-in
pregenerator. In that mode every chunk is generated by vanilla code and kept,
the GPU kernels run as well, and the two results are compared block by block.
One run therefore shows three things:

- **Runs**: the server started and generated every requested chunk to FULL
  with no failed chunks. The CPU-side changes of this mod (parallel steps,
  background saving and loading, the caches) were active.
- **GPU**: whether the kernels could be built for that mod's world generator,
  and if so how many chunks were compared and how many differed.
- **Default behaviour**: what `gpu.mode = "auto"` does with it. A generator
  whose terrain functions have the same structure as a tested one uses the GPU;
  anything else generates with vanilla code. Nothing has to be configured for a
  mod to be safe; `auto` never uses the GPU for a generator it does not
  recognise.

| Mods | Runs | GPU compared with vanilla | Default (`auto`) |
| --- | --- | --- | --- |
| Biomes O' Plenty (with TerraBlender, GlitchCore) | yes | terrain identical, 1,433 chunks; surface rules stay on the CPU (`terrablender:merged` is not a rule type the kernels handle) | GPU terrain, CPU surface |
| Oh The Biomes We've Gone (with its libraries) | yes | terrain identical, 1,560 chunks; surface on the CPU for the same reason | GPU terrain, CPU surface |
| Nature's Spirit (with TerraBlender) | yes | terrain identical, 1,531 chunks; surface on the CPU for the same reason | GPU terrain, CPU surface |
| Geophilic | yes | terrain and surface identical, 1,304 chunks | GPU terrain and surface |
| William Wythers' Overhauled Overworld | yes | terrain and surface identical, 1,406 chunks | GPU terrain and surface |
| YUNG's Better Strongholds, Mineshafts, Dungeons, Ocean Monuments, Desert Temples, Jungle Temples, Witch Huts, Bridges, Extras | yes | terrain and surface identical, 1,288 chunks | GPU terrain and surface |
| Dungeons and Taverns, When Dungeons Arise, Structory | yes | terrain and surface identical, 1,335 chunks | GPU terrain and surface |
| The Lost Cities (default world type) | yes | terrain and surface identical, 968 chunks; its own city generator was not selected, so this only shows the mod's presence is harmless | GPU terrain and surface |
| Regions Unexplored | yes | not used: its terrain uses a Lithostitched density function the kernels do not support | vanilla generation |
| Incendium, Amplified Nether, YUNG's Better Nether Fortresses (Nether) | yes | not used: the Nether terrain these packs define fails one of the kernel compiler's safety conditions | vanilla generation in the Nether |
| Nullscape, YUNG's Better End Island (End) | yes | not used, for the same reason | vanilla generation in the End |
| Lithium 0.15.4 | yes | output identical to a server with neither mod at SURFACE and CARVERS (8,281 chunks) | unchanged |
| Chunky 1.4.23 | yes | `chunky radius 1500` then `chunky start` on the installed server: 35,700 chunks, no errors, 37,124 chunks' terrain from the GPU; Chunky reported 700–1,030 chunks/s | unchanged |

"Identical" means no block differed in the chunks compared. It is evidence for
those chunks, not a proof for every biome a mod adds: each run covered about
1,300 chunks around one spawn.

Where the table says vanilla generation, the mod still works; it only means
that world's terrain is not accelerated. The CPU-side changes still apply.

## Not tested, and why

- **Towns and Towers**: its 1.21.1 release requires NeoForge 21.1.230 or newer;
  this project's development environment is 21.1.176.
- **ChoiceTheorem's Overhauled Village**: fails to load on NeoForge 21.1.176
  with an event-bus registration error of its own, before any world exists.
- **C2ME, Noisium and other mods that rewrite chunk generation or its
  threading**: not tried. They change the same code this mod does; expect
  conflicts.
- Any of the above in a client, on Linux, on another GPU, or combined with each
  other. Each group was tested alone.

## Errors seen in the logs

None came from this mod or from chunk generation. Biomes O' Plenty, Oh The
Biomes We've Gone and William Wythers' Overhauled Overworld each logged one
NeoForge message about entities without spawn-placement registration; Regions
Unexplored logged one about a client-only class on a dedicated server; the
structure packs logged advancement-loading errors for recipes they reference.
These runs were not repeated without WorldgenNext, so that they are unrelated
is my reading of the messages, not a measured comparison.

## If your mod is not listed

Set `gpu.mode = "check"` in `config/worldgennext.toml`, generate a few thousand
chunks, and read `/worldgennext status`. See the README.
