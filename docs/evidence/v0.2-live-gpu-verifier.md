# Isolated GPU live/downstream verifier — 2026-09-30

The rebuilt verifier now passes a **one-case real GPU NOISE publication and
independent original comparison**. This is not the complete live GPU matrix,

## Implemented route

The logical endpoint runner previously always installed the CPU provider.
`scripts/replay-minecraft-logical.ps1 -Backend GPU_IEEE_BITS` now selects a
separate GPU verification composition for NOISE, FULL or SAVED/reopen. The
default remains `CPU_OWNED`; unknown backends and native-draft labels fail
closed. Gradle explicitly forwards and validates the selector.

The isolated GPU provider uses a persistent executor and `generateDevice`,
not the CPU-vs-GPU replay API. Actual Minecraft BIOMES/structure inputs are
captured at the existing ownership seam; material output executes on the
device, then uses the existing result validator, mutation journal, coordinator
and NOISE postprocessing. Original downstream stages and serialization remain
the game implementations. No automatic CPU fallback is installed.

This provider has an empty qualified-context allowlist and cannot pass the
evidence-bearing production registry. CPU_ONLY rejects its construction before
native initialization. The disposable logical verifier retains the existing
coordinator-thread publication policy to avoid waiting on its own blocked server
mailbox. That policy is **verification-only**, not a qualified production
threading design. Execute after isolated GPU replay prerequisites, not as a
substitute for them.

## Separate execution and publication

Each debug result has distinct artifacts:

- `.chunk`: encoded complete candidate result.
- `.gpu-receipt.json`: `BACKEND_VALIDATED`, compiled shader/SPIR-V hashes,
  device/driver, context and execution identities, and **zero committed blocks**.
- `.gpu-commit.json`: `COMMITTED` only after the coordinator publication and
  original NOISE tail succeed; failures retain `FAILED` and zero committed.
- `.candidate-status`: `PASS/COMMITTED` only after successful completion.

The runner checks per-core execution-to-publication linkage, backend, ABI,
compiler, coordinates, epoch, counts and artifact provenance before comparing
logical snapshots against the independent original corpus. Missing publication
is not a successful backend result. Debug artifacts use create-new writes;
duplicates cannot overwrite earlier execution evidence.

The actual mutation adapter now creates the committed execution receipt only
after its journal succeeds. The GPU backend receipt remains immutable with
zero committed rows; a failed mutation cannot acquire publication counts.

Storage ABI counters include explicit air tails; `logicalGpuElements` separately
states actual device-produced rows. Neither is a count of native dispatches or a
TPS measurement. These receipts explicitly deny independent parity and release
qualification until the separate comparison is performed.

Logical server batches and independent comparisons now run through a bounded
owned-process helper. Deadline/nonzero failures retain logs/status; only the
known worker PID tree may be terminated. Process exit is not parity success.
Reopened SAVED batches use the same world with new process log directories.
