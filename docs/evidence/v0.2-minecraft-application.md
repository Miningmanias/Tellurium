# v0.2 Minecraft application and commit preflight

This is a loader-side P09 boundary preflight, not live NOISE qualification.

## Executed command

```powershell
$env:JAVA_HOME = 'C:\Program Files\Eclipse Adoptium\jdk-21.0.12.101-hotspot'
.\gradlew.bat :neoforge-1211:gameSmoke --no-daemon
```

The run used Minecraft 1.21.1, NeoForge 21.1.176 and Java 21. The server ran
the real NeoForge GameTest environment and shut down cleanly:

```text
11 tests are now running
========= 11 GAME TESTS COMPLETE =========
All 11 required tests passed :)
BUILD SUCCESSFUL
```

The application tests create a real 1.21.1 `ProtoChunk` at `BIOMES`, resolve
canonical block states through the live block registry, apply a complete dense
result with named heightmaps and postprocessing metadata, and roll the exact
mutation back. The injected-failure test then fails after each mutation phase
and proves that block storage, heightmaps, postprocessing and dirty state are
restored. A second test routes the same target through
`CommitCoordinator` and `MinecraftChunkCommitter`, checks context/registry
identity, ownership status/revision and execution provenance, publishes once,
and proves that the consumed `CommitToken` cannot publish a duplicate.

The same run also confirms that the version-pinned `ChunkStatusTasks.generateNoise`
Mixin bypasses without an enabled/qualified provider and does not create a
replacement future. This proves the conservative mutation and receipt boundary in isolation. It
does not prove a live generation hook, complete candidate NOISE semantics,
qualified GPU execution, FULL downstream completion, SAVED/reopen parity, or
the required matrix. The production hook remains disabled until those gates
are independently qualified.
