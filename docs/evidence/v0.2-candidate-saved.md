# v0.2 candidate SAVED/reopened verification witness

Date: 2026-09-13. Workspace: `D:\Projects\WorldgenNext`. Scope: one
vanilla Overworld candidate run at seed `0`, chunk `(32,32)`, using the
real WorldgenNext CPU NOISE route inside a NeoForge 21.1.176 server.

## Independent reference

The reference was captured first with two clean `oracle-1211` processes:

```powershell
$env:JAVA_HOME = 'C:\Program Files\Eclipse Adoptium\jdk-21.0.12.101-hotspot'
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\capture-original-saved.ps1 `
  -OutputRoot .\build\oracle-saved-check-32-20260913 `
  -RunRoot .\build\oracle-runs\saved-check-32-20260913 `
  -Seed 0 -Dimension minecraft:overworld -ChunkX 32 -ChunkZ 32
```

The original expected and reopened snapshots compared equal across all ten
logical fields. Their independent reference hashes are recorded in
`build/oracle-saved-check-32-20260913/saved-reopen-report.json`.

## Candidate command and result

The candidate helper uses two separate `candidateLogicalSmoke` processes. The
first requires at least one real candidate NOISE request, reaches FULL,
completes `saveEverything(false, true, false)`, and writes the logical
snapshot. The second reopens the same candidate world in a fresh process and
allows zero new NOISE requests because the target is already persisted.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\capture-candidate-saved.ps1 `
  -ReferenceRoot .\build\oracle-saved-check-32-20260913 `
  -OutputRoot .\build\candidate-saved-reopen-32-20260913b `
  -RunRoot .\build\run\candidate-saved-reopen-32-20260913b `
  -Seed 0 -Dimension minecraft:overworld -ChunkX 32 -ChunkZ 32
```

Observed output:

```text
PASS CAPTURE_COMPARISON fields=10 differences=0
PASS CAPTURE_COMPARISON fields=10 differences=0
PASS CAPTURE_COMPARISON fields=10 differences=0
PASS candidate SAVED/reopened smoke
```

The three comparisons are candidate expected versus the independent
reference, candidate expected versus its fresh-process reopen, and candidate
reopen versus the independent reference. The report is
`build/candidate-saved-reopen-32-20260913b/saved-reopen-report.json`.

The logical results were exact even though the files are not byte-identical:
the reference hash is `201AEA4CD2D0A6295F9B8B5501047270EE86B7AE2A037BAA6F3F8A343E3E9D2E`,
while both candidate hashes are
`E2BBC3B1BFBE2B5ED107A54C1A8E2EA65274D5F1C926C3ABA91FA9C959808536`.
The differing headers deliberately preserve producer provenance; canonical
logical comparison, rather than compressed or header bytes, is the required
criterion.

## Limits

This is a one-case P10 implementation and verification witness. It does not
close the required 216-case FULL or SAVED/reopened matrix, P09 live commit
qualification, GPU parity, terrain-mod matrix, stability campaigns,
performance baseline, or G12 release status. The live generation hook remains
disabled.
