# v0.2 Nether GPU candidate staging probe

Status: **NOT QUALIFIED**. Updated 2026-09-21.

This note records the real-device exercises of the one-branch Nether captured
density route. A native-draft GPU artifact now exists and has an independent
CPU comparison, but it is explicitly unqualified because it uses native
floating-point operations. The exact `GPU_IEEE_BITS` route still has no
candidate corpus qualification, but the one-case exact artifact recorded
below now exists and is independently compared with the CPU result.

## Implementation change

The captured Nether final-density root has one direct density branch. The
earlier candidate executor required the Overworld-specific two-branch split and
rejected Nether before doing device work. The draft now sends both shapes
through `executeStagedDensityRoot`: interpolation boundaries are sampled on
their lattice corners, direct graph stages are dispatched in child-before-parent
order, and the resulting density carrier feeds the shared aquifer, ore and
material stages. The previous monolithic dense fallback was removed because it
made the captured Nether module grow to an unbounded native compiler workload.

## Device attempts

All attempts used Java 21, NeoForge 21.1.176, seed `0`, the pinned development
Minecraft stack and the RTX 5070 Ti. The server itself reached normal readiness
before the candidate path was exercised.

| `gpu-nether-staged-20260914` | The default two-octave static grouping reached the staged noise fan-out and compiled many bounded modules, but did not reach fan-in/material completion during the bounded observation window. Stopped externally at about 3 GB working set. |

`neoforge-1211/build/run/`. None of those three roots contains a `.chunk`
result or `GPU_IEEE_BITS` receipt. The later one-octave exact run below shows
the smaller compiler unit that completed the captured 40-sample fan-out.

## Initial exact-profile retry — 2026-09-20

The same real-server Nether capture was retried without the native-draft
property. The `GPU_IEEE_BITS` route entered `vkCreateComputePipelines` while
building the first blended-noise stage and remained there for the bounded
observation window. The run was terminated after the stall to protect the
host; it wrote no `.chunk` artifact, receipt or parity result. This is a
compiler-envelope diagnostic, not an exact arithmetic failure or a pass.

The initial exact attempt was a compiler-envelope diagnostic, not an exact

## Cleanup / follow-up

The static group size, per-group pipeline reclamation and optional device
recreation controls are draft driver-envelope aids. Keep them for diagnosis,
but replace them with a structured policy and a bounded compiled-cache strategy
before release. Add a row-layout/field-preservation test and device-local
allocator ownership before enabling the resident path by default. Do not count
server readiness or a native compile start as GPU generation success.
