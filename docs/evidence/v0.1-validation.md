## Replay and native findings

The CPU replay passed **8/8 fixtures and1,048/1,048 raw-bit comparisons**, zero mismatches. [CPU artifact](v0.1-cpu-replay.json). It compares the prebound compiler against the independent reference interpreter and reports zero GPU samples. Separate unit tests also use analytic answers and a golden interpolation-order case.

The first native attempt failed during Vulkan extension enumeration because LWJGL's default64KiB stack was insufficient on this driver. The replay launchers now set `org.lwjgl.system.stackSize=2048` (KiB) before native initialization. This failure was not counted as a comparison pass; its local log is `build/validation/gpu-smoke-r01-stack-failure.log`.

The default strict native check then failed closed. RTX5070Ti advertised FP64, signed-zero preservation and nearest-even rounding, but not FP64 subnormal preservation. The integrated Intel device lacked shaderFloat64. The report records **0/1,048 comparisons and FAILED**, despite zero measured mismatches. [Strict failure artifact](v0.1-gpu-strict.json). The missing comparison is never treated as parity.

A separate explicitly limited diagnostic uses a different corpus ID and backend. It excludes the subnormal-addition graph, retains the seven other fixed graphs and131 points per graph, and still compares every result against the independent CPU interpreter. On RTX5070Ti it passed **7/7 fixtures and917/917 comparisons**, zero mismatches. These include negative coordinates, lazy overflowing branches, range boundaries, both interpolation geometries, outer semantic boundaries, negative zero and partial workgroups. [Normal-range native artifact](v0.1-gpu-normal-range.json) records device/driver, input/expression hashes and compiled GLSL/SPIR-V hashes per fixture.

Normal-range success does not satisfy strict or general FP64 qualification. Advertised support describes available modes, not proof that a shader enabled them; explicit mode emission and broader qualification remain open. [Khronos property definitions](https://docs.vulkan.org/refpages/latest/refpages/source/VkPhysicalDeviceFloatControlsProperties.html).

Both Gradle tasks and the generated standalone Windows launcher were exercised. The launcher returned0 for CPU and normal-range GPU execution, and1 for the strict unsupported-device result. Native runs were serialized; no CPU substitution or old-mod benchmark was running alongside them.
