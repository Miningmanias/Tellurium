# Code review of 2026-10-07: what was changed

The review (`CODE_REVIEW_2026-10-07.md` in the working tree, of commit `067f3e6`) lists 34 suggested
changes, R01 to R34, from reading the code. This page says what was done about each. It was done quickly on
request: the checks are the unit tests (584 pass), one exactness row (vanilla Overworld, SURFACE, 8,281
chunks identical, all on the GPU) and one kill-and-resume run (PASS), on NeoForge 1.21.1. No new test was
written for these fixes, the full release check was not run, and the other builds were only compiled.

## Changed

| # | Change |
| --- | --- |
| R01 | A region header is only put off for a chunk that had no place in the file yet. A chunk that replaces an earlier copy frees sectors another write may reuse, so its header is written at once, as in the original |
| R02 | A deferred header is forgotten only after it was written; a failed write stays owed and the flush that asked reports it |
| R03 | Staged executor: a pipeline evicted from the cache during a submission is destroyed after that submission is proven over, not while the chain still holds it |
| R04 | A failed `vkQueueSubmit` gives the device up (reason recorded): nothing more is submitted and later chunks go to the original code |
| R07 | Pregeneration resumes no further than the first request that was not answered (a watermark over answered requests), and still two windows back from the last request. Not a proof of what was saved; see below |
| R08 | Only the current job writes or deletes the progress file, one writer at a time, through a uniquely named temporary file and an atomic move where the file system has one |
| R09 | A batch whose results cannot be read back, or a chunk whose apply cannot be scheduled, is generated by the original code instead of being left unanswered |
| R10 | The GPU result is checked (size, palette indices) and all replacement sections are built before any is put into the chunk |
| R11 | The extracted GPU runtime is identified by the content of its jars; a cached jar is compared byte for byte and replaced if it differs |
| R13 | One biome index per parameter list: built under a lock, so the first lookups cannot use an index that is then replaced |
| R15 | A closed Distant Horizons generator starts nothing more, answers its waiting requests as cancelled, and gives its turn back when taking a tile fails |
| R16 | The per-column memo for Distant Horizons' rough generator needs every node of the part to be of a kind known not to read the height (noises with a vertical scale of zero); trying heights is only a second look |
| R17 | Result decoding refuses heights above 4,096 and inputs shorter than their header promises before allocating |
| R18 | Publishing needs validated coverage and no prior commit claim before the token is used, and a committer may not change the execution's counts or commit nothing |
| R19 | An invalidated waiting request leaves the work queue |
| R20 | `LegacyRandom.nextLong` adds the low word signed, as Java and Minecraft do |
| R21 | A one-point spline is that point's value |
| R22 | The raw-chain input length is checked as a whole before it is cut into batches |
| R23 | A fused request with aquifers or ore veins on must carry their captured random source |
| R25 | Bytes of a failed, quarantined dispatch stay counted against the native budget |
| R26 | A closed or too-small result buffer is not given validated coverage |
| R27 | The report checker needs whole-number requested/completed/failed counts, a positive request equal to the radius' square, and no failures; the matrix requires each digest to list exactly the measured number of chunks |
| R28 | The kill check fails if no progress was seen, nothing was running to kill, the job had already finished, the files are invalid right after the kill, or the resumed server exits unsuccessfully; terrain is counted apart from points of interest and entities |
| R29 | Two snapshots with empty block data are a difference, not a covered case |
| R30 | Capture keys escape `/` and `%` inside components |
| R31 | Heightmap values are separated in the logical checksum (existing checksums of this kind change) |
| R32 | A bail-out is counted once, and the surface comparison counters are reset when a server session ends |
| R34 | The v0.2 gate needs an execution report with every required gate passed and evidenced, not the plan with its status flag changed |

Tests changed with the contract: test committers now return committed coverage (R18), and the budget test
expects quarantined bytes to stay reserved (R25).

## Not changed

| # | Why |
| --- | --- |
| R05 | Save listeners on NeoForge 1.21.1 can see chunk data with deferred placeholders. Resolving before the event means doing the encoding on the server thread again whenever a listener exists, which needs a way to know that; not attempted here |
| R06 | The save backlog is not hard-bounded. A real bound means holding back unloads, which is a change to how the server sheds memory and needs a slow-disk test to tune |
| R12 | Binding automatic GPU use to the tested graphics card and driver would switch the GPU path off for everyone on other hardware. That is a product decision, not a fix |
| R14 | Shared structure-piece state under parallel features: needs a design (per-start locking or serialising unknown piece types) and a reproducing world |
| R24 | Hoisting in the fused compiler changes kernel text for listed generators, so every tested-generator list would have to be redone; the finding is an unnecessary fallback, not wrong terrain |
| R33 | Wider saved-world evidence (ticks, block entities, light) is new test work |
| R07 (part) | The resume point is still not tied to chunks being saved; a durable watermark needs the save path to report publication |
| R03, R04, R09, R10 | Changed as above but without failure-injection tests |
